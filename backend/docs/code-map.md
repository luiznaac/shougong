# Code map

Module → key files → seam index for the `backend/` lane, plus the app entry points. FastAPI hexagonal service: `application → (httpapi|persistence|gateway|srs|segmentation|randomization) → usecase`; each package under `src/shougong/` is one block below, then the migration/test/build clusters. Vocabulary: **module**, **interface**, **seam**, **adapter**.

## Modules

### `usecase` — domain, ports and services
**Purpose**: the pure core — frozen dataclasses, `typing.Protocol` ports (`I*` prefix) and the services per slice: dictionary, study + SRS, strokes, reading/vocabulary, study-item history, insights, plus `commons/` and the transaction port. It must not import `fastapi`, `sqlalchemy`, `httpx`, `uvicorn`, `pydantic`, `fsrs` or `jieba`; import-linter enforces it.
**Files**: `backend/src/shougong/usecase/dictionary/{model,pinyin,service,gateway,telemetry,import_policy}.py`; `usecase/study/{model,service,gateway,shuffler,telemetry}.py`; `usecase/srs/{model,engine,day_boundary}.py`; `usecase/strokes/{model,service,gateway,telemetry}.py`; `usecase/reading/{model,service,topic_service,vocabulary_service,gateway,dialogue,speakers,topics,proficiency,validation,working_set,vocabulary,telemetry}.py`; `usecase/study_item_history/{model,service,gateway}.py`; `usecase/insights/{model,policy,gateway,service,overview_service,telemetry}.py`; `usecase/hanzihero/{model,gateway,service}.py`; `usecase/health/{checker,gateway,telemetry}.py`; `usecase/configuration/transaction.py`; `usecase/commons/{asyncx,exceptions,logging,request_context,time}.py`
**Seam(s)**:
- **Ports (`I*` Protocol)** — `IDictionaryRepository`/`ICedictSource`/`IOfficialHskSource`/`IHskDatasetSource` (`dictionary/gateway.py`), `IStudyItemRepository` (`study/gateway.py`; `prioritise`/`deprioritise`/`list_for_session` above the `list` method that must stay last), `IShuffler` (`study/shuffler.py`), `ISrsEngine` (`srs/engine.py`), `IStrokeRepository`/`IHanziStrokeSource` (`strokes/gateway.py`), `IReadingTextGateway`/`ISegmenter`/`IReadingHistoryRepository`/`IReadingWordUsageRepository`/`IReadingTopicRepository` (`reading/gateway.py`), `IStudyItemHistoryRepository` (`study_item_history/gateway.py`), `IInsightRepository` (`insights/gateway.py`), `IHealthChecker`/`IHealthGateway` (`health/`), `IClock` (`commons/time.py`). Every adapter explicitly inherits its port, so mypy and the IDE can jump port ↔ implementation.
- **`ITransactionTemplate.execute(...)`** (`usecase/configuration/transaction.py`) — lets a service compose several repository calls atomically without importing SQLAlchemy; nested calls join the outer transaction.
- **Domain errors** (`usecase/commons/exceptions.py`) — `DomainError` and its `InvalidArgumentError`/`ResourceNotFoundError`/`ConflictError`/`InvalidRangeError` subclasses map to 4xx (400/404/409/422) at `httpapi`'s exception handlers; `ReadingGenerationError` (reading slice) is the one that maps to 502; nothing raises an HTTP type here.
- **Clock seam** (`usecase/commons/time.py`) — logic reads time through `IClock`, never `datetime.now()`; tests pass a fixed clock into `Container(settings, clock=...)`.
- **Insight rules** (`usecase/insights/policy.py`) — the leech window/threshold/ordering and the Extra Study range constants; `InsightService` returns the id→leech map from one batched window read and both buckets, and its port exposes no write method at all.
- **Reading behaviour** (`usecase/reading/`) — `ReadingService` orchestrates the LLM gateway + segmenter + repositories; the LLM prompt itself is the product-behaviour file `gateway/reading/system_prompt.txt`. `ReadingGenerationError` carries a bounded `ReadingFailureCode` (`timeout`, `gateway_unreachable`, `gateway_rate_limited`, `gateway_http_error`, `no_tool_call`, `malformed_tool_call`, `empty_text`, `_OTHER`) and declares `suppress_log_message`, so the log chokepoint keeps `exception.type`/`.stacktrace` and drops `.message`.
- **Reading telemetry** (`usecase/reading/telemetry.py`) — `ReadingTelemetry` owns the slice's instruments (`reading.generated`, `reading.generation_failed`, `reading.correction_attempts`, `reading.extra_words`, `reading.budget_exceeded`, the verbatim `gen_ai.client.inference.usage.{input,output}_tokens` counters and the `gen_ai.client.inference.duration` histogram) plus the `reading.generation_degraded` WARN; `ReadingService` times each gateway attempt monotonically and records through it after the history save, and the composition root calls `record_jieba_warmup_failure` from the background task boundary (`job.id`, one ERROR). The extended duration buckets and the family's attribute allowlists live in `application/telemetry.py`'s SDK views.
- **Log bridge and correlation** (`usecase/commons/logging.py`, `usecase/commons/request_context.py`) — structlog is the call-site API but feeds stdlib `logging`; a terminal processor splits the event name (body) from attributes, redacts secrets/bodies and drops learner-content keys whole-key and case-insensitively, and `ContextVar`s carry `request.id` / `job.id` into every record. The OTel SDK stays out of `usecase` (static test).
- **Health instruments** (`usecase/health/telemetry.py`) — `HealthTelemetry.record(result)` updates the `health.check.status` gauge and `health.check.failures` counter and logs only on a WARN/INFO transition; it never performs I/O.
- **Dictionary instruments and events** (`usecase/dictionary/telemetry.py`) — `DictionaryTelemetry` owns `dictionary.searched` (hit/miss, metric-only) and the `dictionary.autoload_failed` counter+ERROR pair, plus the INFO bootstrap outcomes (`source_downloaded`, `populated`, `populate_skipped`, `hsk_enriched`, `hsk_enrich_skipped`, `import_cleaned`); the skip event carries `dictionary.enrichment_version`, and `source_downloaded` names `cedict`, `official-hsk`, `community-hsk` or `hsk_characters`. `DictionaryService` records through it and the gateways emit nothing.
- **Import policy** (`usecase/dictionary/import_policy.py`) — the set-level rule shared by import and the in-place cleanup: `is_variant_gloss` reads the primary gloss (`variant of`, `old variant of`, `erhua form of`) so a real entry that only notes a variant later stays real; `duplicate_key` is the `(simplified, pinyin, definitions)` triple behind a `DuplicateKey` alias; `_flagged` is the shared decision (duplicate key or variant-with-a-real-sibling); `apply_import_policy` keeps the unflagged `CedictRecord`s and `select_cleanup_ids` returns the flagged stored `DictionaryEntry` ids, never ones a study item or its history references.
- **Grouped search** (`usecase/dictionary/{model,service}.py`, `persistence/dictionary/repository.py`) — `DictionaryService.search` returns `Page[DictionaryWordGroup]`: entries group by `(simplified, pinyin)` **before** pagination (the SQL groups for the page keys and the exact group total), each group carrying its shared word-level fields plus per-meaning `entry_id`/definitions; `group_entries` is the pure assembly-and-order rule the fake repository shares.
- **Versioned enrichment** (`usecase/dictionary/service.py`) — `DictionaryService.enrich_hsk` reads the persisted `enrichment_version` from `IDictionaryRepository` and skips while it matches the code's version (supplied by `Container` as `DICTIONARY_ENRICHMENT_VERSION`); otherwise it cleans alias/duplicate rows via `select_cleanup_ids`, joins the official HSK 3.0 levels (`IOfficialHskSource`) to the community POS tags (`IHskDatasetSource`), clears then re-stamps the dictionary in place, upserts the character-level `character_writing_level` store from `IHskCharacterSource`, derives every word's `handwriting_level` with `derive_handwriting_level` (`usecase/dictionary/model.py`), and persists the new version plus the official per-level totals. A word outside the official list ends with no level. An empty table or an empty download leaves the marker unset so a later run re-runs it.
- **Insights gauges** (`usecase/insights/telemetry.py`) — `InsightsTelemetry` creates the six last-observed gauges once; the overview read records the five study gauges (stage, difficulty band, due depth, seven-day forecast, leeches) and the vocabulary summary records `vocabulary.known_words`. The callbacks replay a stored snapshot, so no gauge performs I/O and no poller exists.
- **Study instruments and curated events** (`usecase/study/telemetry.py`) — `StudyTelemetry` owns the eight learning/SRS + engagement instruments and the three INFO events (`study.item_added`, `study.session_created`, `study.batch_imported`); `StudyService` emits reviews from the pre-review card state, graduates only on a `learning`→`review` transition, and maps import-row failures to the bounded `ImportSkipReason`.
- **Stroke cache outcomes** (`usecase/strokes/telemetry.py`) — `StrokesTelemetry` owns the three attribute-free `strokes.lookup_hit`/`_fetched`/`_missed` counters and the `strokes.warm_failed` ERROR; `StrokeService` increments exactly one counter per lookup and emits no log on the hot path, and `warm` binds the background task's `job.id`.
- **Queue priority and sessions** (`usecase/study/`) — `StudyService.prioritise`/`deprioritise`/`session`; the domain carries `priority_position` as an opaque key, and `IShuffler` is injected so ordering tests substitute a deterministic double instead of patching randomness.
- **HanziHero connection** (`usecase/hanzihero/`) — `HanziHeroService.connect` performs the login through `IHanziHeroLoginGateway` and persists only the session cookie + `connected_at`; a rejected login raises `HanziHeroAuthenticationError` before any write, and a re-connect keeps the prior `last_synced_at`. `status` returns `connected`/`connected_at`/`last_synced_at` (the last stays null until the first sync). Neither port carries the email/username or password into the domain.

### `persistence` — SQLAlchemy adapters and migrations
**Purpose**: async SQLAlchemy 2 repositories, one sub-package per usecase slice, over MySQL via `asyncmy`.
**Files**: `backend/src/shougong/persistence/configuration/{base,database,transaction,time}.py`; `persistence/dictionary/{entity,repository}.py`; `persistence/study/{entity,repository}.py`; `persistence/study_item_history/{entity,repository}.py`; `persistence/insights/repository.py`; `persistence/strokes/{entity,repository}.py`; `persistence/reading/{entity,topic_entity,word_usage_entity,repository,topic_repository,word_usage_repository}.py`; `persistence/hanzihero/{entity,repository}.py`; `persistence/health/mysql_health_check.py`
**Seam(s)**:
- **Declarative base** (`configuration/base.py`) — every entity module must be imported in `alembic/env.py` so `Base.metadata` is complete; there is no aggregate models module.
- **Transaction adapter** (`configuration/transaction.py`) — `SqlAlchemyTransactionTemplate` implements `ITransactionTemplate`; repositories obtain the bound session via `current_session()`, which raises outside a transaction.
- **Entity/repository seam** — a new table is a `persistence/<slice>/entity.py` + registration in `alembic/env.py`; a repository always receives the transaction template, never a session factory.
- **Enrichment marker** (`persistence/dictionary/{entity,repository}.py`) — `dictionary_enrichment_state` holds one row (`id = 1`); `enrichment_version()`/`official_level_totals()` read it and `set_enrichment_version()` upserts the version plus the official per-level totals with `INSERT ... ON DUPLICATE KEY UPDATE`. `list_all()`/`protected_entry_ids()`/`delete_entries()` feed the in-place cleanup: protected ids come from `study_item.entry_id` and `study_item_history.entry_id`, and deletes are batched.
- **Character store and handwriting derivation** (`persistence/dictionary/{entity,repository}.py`) — `character_writing_level` is keyed by character; `apply_character_levels()` upserts it, `simplified_forms()` feeds the rollup, and `set_handwriting_levels()` writes `dictionary_entry.handwriting_level` in batches.
- **Priority edge maths** (`persistence/study/repository.py`) — `prioritise` reads the min/max position under `FOR UPDATE` and writes the pin in the same transaction; `update_card` deletes the pin on a `learning`→`review` graduation; `get`/`get_many`/`list`/`list_for_session` outer-join `study_item_priority` so `priority_position` is populated.
- **Insight reads** (`persistence/insights/repository.py`) — one windowed aggregate for the grade windows, one grouped count+page for Recent Mistakes and one lag-based count+page for Recently Learned.
- **Single-row connection** (`persistence/hanzihero/`) — `hanzihero_connection` holds one row (`id = 1`); `save` merges over it, so connect is an upsert and the table can never hold two sessions.
- **Health adapter** (`health/mysql_health_check.py`) — implements `IHealthChecker` over the shared engine and never raises.

### `gateway` — outbound HTTP integrations
**Purpose**: httpx adapters for CC-CEDICT, the official HSK 3.0 word list, the community POS dataset, the official handwriting character list, Hanzi Writer stroke data, the HanziHero login handshake, the LiteLLM reading proxy and the self-health probe.
**Files**: `backend/src/shougong/gateway/configuration/http_client.py`; `gateway/dictionary/{cedict_source,official_hsk_source,hsk_dataset_source,hsk_character_source}.py`; `gateway/reading/litellm_reading_gateway.py`, `gateway/reading/system_prompt.txt`; `gateway/strokes/hanzi_writer_source.py`; `gateway/hanzihero/login_gateway.py`; `gateway/health/{app_health_gateway,http_client_health_check}.py`
**Seam(s)**:
- **Source adapters** — `CedictSource`/`OfficialHskSource`/`HskDatasetSource`/`HskCharacterSource` implement the dictionary sources (the character one parses the official handwriting CSV and normalises the 7-9 band to 7); `HanziWriterSource` implements `IHanziStrokeSource`; `LiteLlmReadingGateway` implements `IReadingTextGateway`. All share `build_http_client()`.
- **Gateway failure taxonomy** (`gateway/reading/litellm_reading_gateway.py`) — every raise site sets a bounded `ReadingFailureCode`; messages are static/status-only (no upstream body), and any unclassified failure becomes `_OTHER`.
- **Model label cache** (`gateway/reading/litellm_reading_gateway.py`) — `list_models` warms a cached proxy model list with a 5-minute refresh floor, and the synchronous `model_label` resolves `gen_ai.request.model` from that cache (`_OTHER` on a miss or an unreachable proxy) so generation never blocks on the list.
- **Outbound correlation** (`configuration/http_client.py`) — a request hook copies the bound `request.id` onto every outbound call as `X-Request-ID`; the `HTTPXClientInstrumentor` (installed by the composition root) owns `http.client.request.duration`.
- **Prompt seam** (`gateway/reading/system_prompt.txt`) — product behaviour, not config: changing it changes every generated reading, so review it like a usecase change.
- **HanziHero login** (`gateway/hanzihero/login_gateway.py`) — `HanziHeroLoginGateway` runs the Phoenix cookie handshake against `HANZIHERO__BASE_URL`: fetch the login page, read the `_csrf_token` and pre-login cookie, POST `user[email_username]`/`user[password]`/`user[remember_me]`, and return the session cookie on the redirect. It owns a cookie jar scoped to the handshake so a stale session cannot make the login page redirect; the password and identifier are never logged or returned.
- **Self-health** (`gateway/health/`) — `AppHealthGateway` probes `GATEWAYS__APP__HOST` (the service's own `/health/internal`); `HttpClientHealthCheck` adapts it to `IHealthChecker`.

### `srs` — FSRS scheduling adapter
**Purpose**: the FSRS engine adapter plus the day-boundary wrapper that fixes when cards become due.
**Files**: `backend/src/shougong/srs/fsrs_engine.py`; `backend/src/shougong/usecase/srs/day_boundary.py`
**Seam(s)**: **`FsrsEngine`** (`srs/fsrs_engine.py`) implements `ISrsEngine`; `DayBoundaryEngine` (`usecase/srs/day_boundary.py`) wraps it with the configured study timezone, so a scheduling change chooses deliberately which layer it lands in.

### `segmentation` — jieba adapter
**Purpose**: word segmentation and POS tagging for reading generation.
**Files**: `backend/src/shougong/segmentation/{jieba_segmenter,jieba_pos}.py`
**Seam(s)**: **`JiebaSegmenter`** (`segmentation/jieba_segmenter.py`) implements `ISegmenter`; `jieba_pos.py` adds POS tags. Import-linter keeps jieba out of `usecase/`.

### `randomization` — system-random adapter
**Purpose**: the production shuffle source for lesson/review sessions.
**Files**: `backend/src/shougong/randomization/random_shuffler.py`
**Seam(s)**: **`RandomShuffler`** implements `IShuffler` over `random.SystemRandom`; inject it through `Container`, and substitute a deterministic double in tests.

### `httpapi` — FastAPI controllers and DTOs
**Purpose**: the HTTP surface — controllers returning `APIRouter`s, Pydantic transport DTOs, the app factory and the domain-exception handlers.
**Files**: `backend/src/shougong/httpapi/controller/base.py`, `controller/{health,dictionary,strokes,study,study_session,study_item_history,insights,reading,reading_topic,vocabulary,hanzihero}_controller.py`; `httpapi/schema.py`; `httpapi/configuration/{server,telemetry}.py`
**Seam(s)**:
- **`IController.router()`** (`controller/base.py`) — the `ControllerTemplate` equivalent; `Container` builds the controller list and `build_app` mounts each router, so adding an endpoint never edits the server wiring.
- **DTO seam** (`schema.py`) — Pydantic lives only here (and in `application/settings.py`); every response has a `from_domain(...)` classmethod, and the shapes are mirrored in `frontend/src/api/types.ts` in the same commit. `DictionaryEntryResponse` (and the related/study DTOs that embed it) carries both `hsk_level` (vocabulary) and `handwriting_level`.
- **Error mapping** (`configuration/server.py`) — `_install_exception_handlers` maps `ResourceNotFoundError`→404, `InvalidArgumentError`→400, `ConflictError`→409, `HanziHeroAuthenticationError`→400, `ReadingGenerationError`/`HanziHeroUnavailableError`→502 (a bounded code as `error.type`), `DomainError`→422 with the `{code, detail}` body; each handler stashes `error.type` for the boundary record, and the 502 handler stashes the exception so the single ERROR carries `exception.type`/`.stacktrace` (never `.message`).
- **Request boundary** (`configuration/server.py`) — `RequestContextMiddleware` is outermost: it resolves/echoes `X-Request-ID`, binds it as a `ContextVar`, and owns the single 4xx WARN / 5xx ERROR `http.request.failed` record. `configuration/telemetry.py` is the only place `FastAPIInstrumentor` is applied, from the composition root.

### `application` — composition root and settings
**Purpose**: the one place that knows every concrete class, plus typed settings and the ASGI entry.
**Files**: `backend/src/shougong/application/{container,settings,boot}.py`, `application/telemetry.py`
**Seam(s)**:
- **`Container`** (`application/container.py`) — builds telemetry first, then the engine, HTTP client, every adapter/service (including the `RandomShuffler` and the per-slice `ReadingTelemetry`) and the `controllers`/`health_checkers` lists; installs SQLAlchemy/httpx/FastAPI/runtime instrumentation, `build_app(..., lifespan=...)`, the request-id middleware, and flushes telemetry in `aclose()`. Adding a slice is a class plus one wiring line here. Tests construct their own `Container` with fakes/fixed clock/in-memory telemetry.
- **`build_telemetry`** (`application/telemetry.py`) — the one place the OTel SDK exists: resource (six attributes), providers/exporters (OTLP dev/prod, console when `TELEMETRY_CONSOLE`, in-memory under `APP_ENV=test`), metric views/buckets, the SQLAlchemy pool series, the log bridge, and the 10 s shutdown flush. Prod without `OTEL_EXPORTER_OTLP_ENDPOINT` raises `TelemetryConfigError`.
- **Lifespan** (`application/container.py`) — the async lifespan starts the dictionary/HSK autoload and the jieba warm-up, and cancels them plus `aclose()` on shutdown.
- **Settings** (`application/settings.py`) — `pydantic-settings`, `__`-nested env vars, `APP_ENV` profile; `MySqlConfig.url` is the one DB URL shape. `Settings.app_host` derives the self-health base URL from `HTTP_PORT` unless `GATEWAYS__APP__HOST` is set explicitly; `HanziHeroConfig.base_url` (`HANZIHERO__BASE_URL`) points the login handshake at the real site or a test fake.

### `acceptance` — dev-only fixture
**Purpose**: the committed seed `docs/runbooks/acceptance.md` applies on a clean MySQL so the list- and item-detail-surface walkthroughs need no manual SQL. It is excluded from the production image (`.dockerignore`) and nothing in the service imports it.
**Files**: `backend/src/shougong/acceptance/fixture.py`, `backend/src/shougong/acceptance/stroke_cache.py`
**Seam(s)**: **`build_fixture(now)`** is the pure data plan the unit test pins (more than one 24-row page, every SRS state, both levels spanning 1-6 + the 7-9 band + none, a leech, a pin, the 知道 detail word with a >8-row related family, three readings containing it and cached strokes for both characters); **`apply_acceptance_fixture(settings)`** writes it in one transaction, only when `dictionary_entry` is empty, so re-running the runbook is a no-op; **`_log_outcome(outcome)`** is the CLI's single `acceptance.seed_finished`/`acceptance.seed_skipped` record.

### `alembic`, tests and packaging
**Purpose**: the migration chain and its baseline logic, the unit/integration suites, and the image/CI story.
**Files**: `backend/alembic/env.py`, `alembic/versions/{0001_baseline,0002_dictionary_hsk,0003_reading,0004_study_item_priority,0005_insights,0006_merge_priority_insights,0007_dictionary_enrich,0008_handwriting_levels,0009_enrichment_level_totals,0010_hanzihero_connection}.py`; `backend/scripts/migrate.py`; `backend/tests/unit/*`, `backend/tests/integration/*`, `tests/{conftest,fixtures}.py`; `backend/pyproject.toml`; `deploy/{entrypoint.sh,nginx.conf.template,supervisord.conf}`, `Dockerfile`, `docker-compose.yml`, `.github/workflows/*`
**Seam(s)**:
- **Migration guard** (`alembic/env.py`, `scripts/migrate.py`) — autogenerate + `compare_metadata` against `Base.metadata`; `migrate.py` baselines a pre-migration database by stamping `0001_baseline`, then upgrades to head. Never hand-write SQL.
- **Deploy entry** (`deploy/entrypoint.sh`) — renders nginx, runs `scripts/migrate.py`, then `exec supervisord`; a failed migration aborts the container.
- **Layer contracts** (`pyproject.toml` `[tool.importlinter]`) — the `layers` + `forbidden` contracts are the enforcement behind the dependency rule; `uv run poe contracts` is part of `check`.
- **Test harness** (`tests/integration/conftest.py`) — Testcontainers MySQL + in-process ASGI via httpx + `pytest-httpserver`; `tests/unit/` needs no Docker.

## Entry points

- `backend/src/shougong/application/boot.py` — `app` (what uvicorn imports: `shougong.application.boot:app`) and `main()` (`poe run`), which serves on `HTTP_PORT` (8130) with reload only in `dev`.
- `backend/src/shougong/application/container.py` — the composition root; builds the object graph, controllers and FastAPI app.
- `backend/src/shougong/application/telemetry.py` — `build_telemetry(settings)`: the SDK lifecycle, resource, exporters, metric views, pool series, log bridge and shutdown flush.
- `backend/src/shougong/httpapi/configuration/server.py` — `build_app(...)`: mounts every `IController` router and installs the exception handlers.
- `backend/scripts/migrate.py` — the migration entry (`poe migrate`, `deploy/entrypoint.sh`); baseline-stamp then upgrade to head.
- `backend/alembic/env.py` — Alembic's online/offline environment over `Base.metadata`.
- `backend/tests/integration/conftest.py` — the integration harness entry (Testcontainers MySQL, in-process ASGI).

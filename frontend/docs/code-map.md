# Code map

Module → key files → seam index for the `frontend/` lane, plus the app entry points. React 19 + Vite + TypeScript, Tailwind v4-in-CSS, TanStack Query v5, React Router and hanzi-writer; `api/` → `components/` → `pages/` → `lib/`. Vocabulary: **module**, **interface**, **seam**, **adapter**.

## Modules

### `src/api` — backend adapter and wire types
**Purpose**: the only place that talks HTTP — the fetch wrapper, the hand-mirrored Pydantic DTOs and the TanStack Query hooks.
**Files**: `frontend/src/api/client.ts`, `frontend/src/api/types.ts`, `frontend/src/api/queries.ts`
**Seam(s)**:
- **DTO mirror** (`api/types.ts`) — mirrors `backend/src/shougong/httpapi/schema.py` (`DictionaryEntry`, `CharacterStrokes`, `SrsCard`, `StudyItem`, `ReviewLog`, batch-import and reading shapes, plus `SrsRating`/`SrsState`); update both in the same commit. `CharacterStrokes.medians` are raw hanzi-writer data in a 1024×1024 box with the Y-axis flipped (see `components/StrokeOrder.tsx`).
- **Fetch adapter** (`api/client.ts`) — `BASE` is `VITE_API_BASE ?? "/api"`; `ApiError` carries `status` and the `{detail}` message; `request<T>` treats `204` as `undefined`. A new endpoint adds a method to `api`, not another fetch wrapper.
- **Query seam** (`api/queries.ts`) — the `keys` factory (`studyItemsPrefix`, `studyItems`, `studyItemPages`, `studyItem`, `reviews`, `history`, `dictionary`, `readingHistory`, `insightsPrefix`, `extraStudy`, `studyOverviewPrefix`, `studyOverview`) plus the non-factory keys (`["study-session", kind]` from `lib/studySession.ts`, `["strokes", character]`). `useStudyItems` pages through `api.listAllStudyItems` (backend cap 200) for the pre-redesign surfaces; `useStudyItemPages` is the Hoje grid's one-page-at-a-time infinite query (12 per page, `getNextPageParam` from the envelope's exact `total`). `useCharacterStrokes` sets `retry: false` (a 404 means "no stroke data") and `staleTime: Infinity` (stroke data never changes). `useStudySession` sits outside the `["study-items"]` prefix with infinite stale time and zero cache time, so study-item invalidation never refetches or reshuffles a running session. `useExtraStudy` keys on the two range instants under `["insights"]`, takes its stale time per observer (60 s on the dashboard, infinite in practice), and `invalidateAfterReview` is the single real-grade refresh policy: it invalidates the study-items, insights and study-overview prefixes so the grids, Extra Study and every Hoje aggregate stay current. Adding an item (single or batch) invalidates the study-items and study-overview prefixes for the same reason. Practice calls no mutation, so nothing is invalidated. `priorityMutationOptions` owns the optimistic priority policy: it cancels the study-items queries, writes the predicted edge position into every cached list and the single-item cache, snapshots them for rollback, seeds the single item from the server response, and on settle invalidates the study-items prefix and the lesson-session key.

### `src/pages` — routed screens
**Purpose**: the eight screens — Hoje (dashboard), Biblioteca's Adicionar/Importar CSV, study-item detail, Leitura, and the full-screen lesson/review/practice flows — mounted at the new IA paths (`/`, `/biblioteca/*`, `/leitura`). Biblioteca's item index, Progresso and Ajustes render the shared `Placeholder` until their own tickets land.
**Files**: `frontend/src/pages/Dashboard.tsx`, `pages/AddItems.tsx`, `pages/BatchImport.tsx`, `pages/StudyItemPage.tsx`, `pages/Reading.tsx`, `pages/Lesson.tsx`, `pages/Review.tsx`, `pages/Practice.tsx`
**Seam(s)**:
- **Hoje dashboard** (`pages/Dashboard.tsx`, `api/queries.ts`) — one `useStudyOverview` request feeds every aggregate: the hero's `due_review_count` / `new_count` and the disabled-at-zero actions (`/review`, `/lesson`), the Caracteres chip counts (`item_count` / `leech_count`), the learned chart, the SRS half-pie and the seven-day forecast. The sticky right rail (`lg:sticky`) holds SRS Stages then Próximas revisões; the DOM order is the settled mobile order (hero → Caracteres → Itens aprendidos → Estudo extra → SRS → Próximas revisões). Each panel owns its loading skeleton and empty copy. The character grid reads one page of 12 at a time through `useStudyItemPages` (`sort=stability_asc` for Todas, `leech=true` for Sanguessugas — the server order is authoritative) and appends via the `+` tile, never paging through the queue.
- **Study session seam** (`pages/Lesson.tsx`, `pages/Review.tsx`, `api/queries.ts`, `lib/studySession.ts`) — each flow reads `GET /study/session?kind=…` once on entry (`staleTime: Infinity`, `gcTime: 0`) and hands the received item order to `Quiz` verbatim — no client filter or sort. The backend owns lesson membership (all `learning`, pinned first then shuffled remainder) and review membership (due, non-learning, fully shuffled); a remount or refresh is a new session with a new shuffle. `useReviewMutation` invalidates the `["study-items"]` prefix, the insights and study-overview prefixes, the single item and its review list, but not the running session.
- **Practice seam** (`pages/Practice.tsx`, `lib/extraStudy.ts`, `components/Quiz.tsx`) — reads `bucket` and the two range instants from the URL, re-reads the same `["insights", "extra-study", …]` query the dashboard used and holds it with infinite stale time, then hands the bucket's items to `Quiz` with `record={false}`. That seam issues no grade request at all; the top bar reads `Prática` with an `SRS intact` chip and the summary says nothing was recorded.
- **Extra Study panel** (`components/ExtraStudyPanel.tsx`, `pages/Dashboard.tsx`, `lib/extraStudy.ts`) — the two fixed buckets as tabs with their server totals always visible, at most four hanzi tiles of the active bucket in received order, and a `Praticar` action disabled at zero. One implicit recent-window insight request (no date inputs) drives the panel; the practice URL carries its range.
- **Priority quick actions** (`components/ItemPrioritySection.tsx`, `pages/StudyItemPage.tsx`, `lib/lessonQueue.ts`) — priority editing lives on the item page only now; the section renders only while the item is still `learning` and reuses `PriorityActions` (front/back/remove with item-scoped names, inline `role="alert"` failures and `aria-busy`). The quiz runner carries no priority controls, so a running session order stays frozen.
- **Reading** (`pages/Reading.tsx`) — composes the generation controls, history, topic panel and vocabulary panel; model choice is persisted client-side (`reading.model`), and numeric inputs are clamped to the backend bounds.
- **Batch import** (`pages/BatchImport.tsx`) — parses the CSV locally, then sends one row at a time and layers `pending`/`loading` display states over the backend outcome.

### `src/components` — chrome, shared primitives, quiz and Chinese-language widgets
**Purpose**: the responsive app shell, the shared component vocabulary, the quiz/lesson machinery, the stroke-order renderers and the reading/vocabulary panels.
**Files**: `frontend/src/components/{AppShell,Placeholder,PageHeader,Panel,Skeleton,EmptyState,Toast,icons,Quiz,HandwritingQuiz,FullScreenMsg,StrokeOrder,StrokeOrderPanel,Pinyin,Hanzi,RelatedEntries,VocabularyPanel,ReadingTopicsPanel,CharacterTileGrid,StudyItemTile,PriorityActions,ItemPrioritySection,ExtraStudyPanel,UpcomingReviews,SrsHalfPie,ItemMetricChart,ItemsLearnedChart}.tsx`
**Seam(s)**:
- **Character tile and grid** (`components/StudyItemTile.tsx`, `components/CharacterTileGrid.tsx`, `lib/tileBadges.ts`) — the one tile used by every character grid and the item page header: hanzi-only, fluid (`aspect-square w-full`) with the SRS level colour on the bottom edge, linking to `/biblioteca/itens/:id`. `tileBadges(item)` derives the overlays from the DTO alone — a ghost for `is_leech`, then a bolt for a non-null `priority_position` — rendered as the drawn `GhostIcon`/`BoltIcon` with a pt-BR `aria-label` and a `title`, never emoji. `CharacterTileGrid` lays tiles out in a fluid `auto-fill` column flow in the received order (never re-sorted) and appends the dashed `+` tile when given `onLoadMore`. The quiz runner renders none of this.
- **Hoje panels** (`components/SrsHalfPie.tsx`, `components/UpcomingReviews.tsx`, `components/ItemsLearnedChart.tsx`) — the three overview-fed panels: the half-pie splits the five display groups in `GROUP_COLOR` order with the total in the centre and a two-column legend (the empty track alone at zero); the forecast renders exactly the seven local-day rows with a quiet proportional bar; the learned chart is chart-only with HTML Y ticks beside the plot and local-date X labels below it. Day labels go through `lib/format.ts`'s local parse — never `new Date("YYYY-MM-DD")`.
- **Shell seam** (`components/AppShell.tsx`, `lib/navigation.ts`) — the desktop sticky command bar (brand, four global sections, `Buscar` + a working `⌘K`/Ctrl+K shortcut, the `Retomar` due chip from `useStudyOverview`, and the account chip for Ajustes) over a `max-w-6xl` content column, plus the mobile top app bar and pinned bottom tabs (Hoje / Biblioteca / Leitura / Mais) with the Mais overflow sheet (Progresso / Adicionar / Ajustes). Every destination, label and icon comes from `lib/navigation.ts`; both mobile edges pad through `lib/safeArea.ts`. `Lesson`/`Review`/`Practice` are routed outside it.
- **Primitives seam** (`components/PageHeader.tsx`, `Panel.tsx`, `Skeleton.tsx`, `EmptyState.tsx`, `Toast.tsx`, `Placeholder.tsx`) — the shared vocabulary every later surface composes: page heading, bounded panel, decorative loading block, per-panel empty guidance, transient undo/dismiss toast and and the one shared stand-in for an unmigrated route (optionally linking its section's already-built sub-surfaces).
- **Icon seam** (`components/icons.tsx`) — the inline stroke-SVG set (`ICON_NAMES`, 24×24, round caps/joins, 1.7 stroke) with the `ghost`/`bolt` badge pair at 2.6; `Icon` is decorative unless given a `label`.
- **Stroke coordinate seam** (`components/StrokeOrder.tsx`, `HandwritingQuiz.tsx`) — converts hanzi-writer's raw (Y-up, top-left at `(0, 900)`) data into a top-down 0..1024 SVG box; `HandwritingQuiz` feeds the same cached data through `charDataLoader` so it never hits a CDN.
- **Quiz phase seam** (`components/Quiz.tsx`) — the `info → prompt → revealed` phase machine over an item queue, with the `RATINGS` (`again`/`hard`/`good`/`easy`) as the review submission and keyboard hotkeys; `HandwritingQuiz` is the optional interactive check. Its `record` prop defaults to true; practice passes false, which skips the grade call entirely while keeping the same runner and local accuracy. `Quiz.dom.test.tsx` exercises the phase contract through the DOM lane: reveal by click, grade by hotkey, advance by Enter.
- **Pinyin rendering** (`components/Pinyin.tsx`) — consumes `lib/pinyin.ts` syllables and the `.tone-1`–`.tone-5` classes from `index.css`.

### `src/i18n` — backend-enum display labels
**Purpose**: pt-BR labels for backend enums that reach the UI.
**Files**: `frontend/src/i18n/partOfSpeech.ts`, `frontend/src/i18n/vocabularyCategory.ts`
**Seam(s)**: **Label maps** — `partOfSpeechLabel(...)` and `vocabularyCategoryLabel(...)` are exhaustive `Record<BackendEnum, string>` maps; a new backend enum value fails the type until it is translated here (same PR as the backend change). `VOCABULARY_CATEGORIES` is the select order.

### `src/lib` — pure helpers
**Purpose**: the unit-testable surface — CSV parsing, pinyin conversion, the display-only SRS ladder, local settings, extra-study range arithmetic and formatting.
**Files**: `frontend/src/lib/csv.ts`, `lib/pinyin.ts`, `lib/srs.ts`, `lib/localSettings.ts`, `lib/format.ts`, `lib/studySession.ts`, `lib/navigation.ts`, `lib/safeArea.ts`, `lib/tileBadges.ts`, `lib/lessonQueue.ts`, `lib/extraStudy.ts`, `lib/quizPractice.ts`
**Seam(s)**:
- **Navigation model seam** (`lib/navigation.ts`) — `PATHS` (every chrome destination, including the resume route), `itemPath(id)`, `SECTIONS` (Hoje / Biblioteca / Leitura / Progresso), `MOBILE_TABS` (the three sections that survive as tabs), `MAIS_ITEMS` plus the shared `ADICIONAR`/`AJUSTES` destinations, and the active-path rules (`isActiveSection`, `isMaisTabActive`). Every chrome and every item link reads this model; a destination is never hard-coded twice.
- **Safe-area constants** (`lib/safeArea.ts`) — `SAFE_AREA_TOP`/`SAFE_AREA_BOTTOM` for the chrome edges and `DOCKED_BOTTOM` for anything floating above the mobile tab bar; `index.html` opts into `viewport-fit=cover` so the insets are real.
- **Tile badge seam** (`lib/tileBadges.ts`) — `tileBadges(item)` returns the ordered ghost/bolt descriptors (ghost first) with their kind, pt-BR label and title; `StudyItemTile` draws each with its icon.
- **Lesson queue and priority seam** (`lib/lessonQueue.ts`) — `isLearning`/`isPinned`/`priorityStatus` drive the item page's priority section; `predictPriorityPosition` and `applyCachedPriority` are the pure halves of the optimistic update; `priorityErrorMessage` owns the pt-BR inline copy, including the 409 graduation sentence.
- **CSV seam** (`lib/csv.ts`) — `parseStudyItemsCsv(text)` accepts a hanzi/pinyin header, comma or semicolon, quoted fields; it never validates pinyin (the backend reports per-row).
- **Pinyin seam** (`lib/pinyin.ts`) — `parsePinyin(numbered)` → `{text, tone}` and `toAccented`; the tone-mark placement rule lives here, not in a component.
- **SRS display ladder** (`lib/srs.ts`) — derived from the backend's continuous `stability` (days), not a stored level; `LEVELS`/`GROUP_ORDER`/`GROUP_COLOR` are the single ladder and palette. The overview owns the group counts; the client only maps a card to its level and colour.
- **Local settings** (`lib/localSettings.ts`) — `useHandwritingEnabled`/`useHandwritingTolerance` persist per browser; `allowedMistakes(strokeCount, tolerancePercent)` scales the tolerance by the character's own stroke count.
- **Session query policy** (`lib/studySession.ts`) — `studySessionKey(kind)` and `STUDY_SESSION_QUERY` pin the session hooks outside the `["study-items"]` prefix with infinite stale time and zero cache time.
- **Extra Study range** (`lib/extraStudy.ts`) — local calendar-day helpers: `toDay`/`addDays`, the last-three-day default window the dashboard uses, `rangeInstants` (from → local midnight, to → next local midnight), the bucket list/predicate, and `parsePracticeSearch` for the practice URL. Local-day parsing itself is `format.ts`'s `parseLocalDay`.
- **Practice copy and write seam** (`lib/quizPractice.ts`) — `topBarTitle`/`summaryCopy` own the practice variant's labels: `Prática`, the `SRS intact` run, and the summary saying nothing was recorded. `submitRevealedGrade` is the only place a revealed advance decides whether to call the grade mutation; with `record: false` it never calls the submit callback, so practice issues no write at all.
- **Formatting** (`lib/format.ts`) — `fromNow`/`formatDateTime`/`formatDate`, all `pt-BR`, plus `parseLocalDay`/`formatDayLabel`/`formatWeekdayLabel` for the overview's `YYYY-MM-DD` local days (parsed from parts, never as UTC midnight).

### `src/test` — two-lane test harness
**Purpose**: the shared fixture and the DOM-lane setup behind Vitest's two projects.
**Files**: `frontend/src/test/studyItemFixture.ts`, `frontend/src/test/domSetup.ts`, `frontend/vitest.config.ts`
**Seam(s)**:
- **Lane split** (`vitest.config.ts`) — `*.test.{ts,tsx}` runs in the node environment (pure helpers, markup-only renders through `react-dom/server`); `*.dom.test.tsx` runs in jsdom with `@testing-library/react` and `@testing-library/user-event`, after `test/domSetup.ts` registers RTL cleanup. An interaction contract — click, keyboard, state change and the visible outcome after it — belongs to the DOM lane; a single-render assertion stays markup-only.
- **Study-item fixture** (`test/studyItemFixture.ts`) — `studyItem(overrides)` builds one minimal `StudyItem`; override only the fields the test is about.

### Theme and root wiring
**Purpose**: the design tokens and the Vite/TypeScript build that serves the SPA.
**Files**: `frontend/src/index.css`, `frontend/vite.config.ts`, `frontend/index.html`, `frontend/package.json`, `frontend/tsconfig*.json`
**Seam(s)**:
- **Theme seam** (`src/index.css`) — the `@theme` block owns the hanzi font, the accent, the pinyin tone colours (`--color-tone-*`), the SRS stage colours (`--color-srs-*`) and the `.tone-*` classes; components consume those names.
- **Safe-area seam** (`index.html`, `lib/safeArea.ts`) — the viewport meta opts into `viewport-fit=cover`, so the shared `env(safe-area-inset-*)` constants (header top, tab bar and floating toast bottom) are non-zero under a notch or home indicator.
- **Base-path seam** (`vite.config.ts`) — `base` is `/shougong/` in production and `/` in dev; `main.tsx` derives the router `basename` from `import.meta.env.BASE_URL`.
- **Dev server** (`vite.config.ts`) — port 5273 with the `/api` proxy to `VITE_API_TARGET ?? http://localhost:8080`.
- **Quality gate** (`package.json`) — `check` runs `typecheck` + `lint` (Biome) + `test` (Vitest, two projects: the node lane — pure helpers in `src/lib` and markup-only renders through `react-dom/server` — and the jsdom lane — `*.dom.test.tsx` interaction contracts through React Testing Library; see `src/test` above).

## Entry points

- `frontend/src/main.tsx` — mounts React `StrictMode` with the `QueryClient` and the browser router.
- `frontend/src/App.tsx` — the route table: `/` under `AppShell` (index `Dashboard`, `biblioteca` → `Placeholder`, `biblioteca/itens/:id`, `biblioteca/adicionar`, `biblioteca/importar`, `leitura`, `progresso`/`ajustes` → `Placeholder`) plus `/lesson`, `/review` and `/practice` outside the chrome.
- `frontend/index.html` — the Vite HTML shell with the `#root` mount.
- `frontend/vite.config.ts` — dev server, base path and API proxy.
- `frontend/src/index.css` — the design-token entry imported by `main.tsx`.

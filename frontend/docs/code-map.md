# Code map

Module → key files → seam index for the `frontend/` lane, plus the app entry points. React 19 + Vite + TypeScript, Tailwind v4-in-CSS, TanStack Query v5, React Router and hanzi-writer; `api/` → `components/` → `pages/` → `lib/`. Vocabulary: **module**, **interface**, **seam**, **adapter**.

## Modules

### `src/api` — backend adapter and wire types
**Purpose**: the only place that talks HTTP — the fetch wrapper, the hand-mirrored Pydantic DTOs and the TanStack Query hooks.
**Files**: `frontend/src/api/client.ts`, `frontend/src/api/types.ts`, `frontend/src/api/queries.ts`
**Seam(s)**:
- **DTO mirror** (`api/types.ts`) — mirrors `backend/src/shougong/httpapi/schema.py` (`DictionaryEntry`, `CharacterStrokes`, `SrsCard`, `StudyItem`, `ReviewLog`, batch-import and reading shapes, plus `SrsRating`/`SrsState`); update both in the same commit. `CharacterStrokes.medians` are raw hanzi-writer data in a 1024×1024 box with the Y-axis flipped (see `components/StrokeGlyph.tsx`).
- **Fetch adapter** (`api/client.ts`) — `BASE` is `VITE_API_BASE ?? "/api"`; `ApiError` carries `status` and the `{detail}` message; `request<T>` treats `204` as `undefined`. A new endpoint adds a method to `api`, not another fetch wrapper.
- **Query seam** (`api/queries.ts`) — the `keys` factory (`studyItemsPrefix`, `studyItems`, `studyItemPages`, `studyItemPageQuery`, `studyItem`, `reviews`, `history`, `dictionaryPage`, `relatedEntriesPrefix`, `relatedEntries`, `relatedEntryPages`, `readingHistory`, `readingHistoryPages`, `itemReadings`, `readingText`, `insightsPrefix`, `extraStudy`, `studyOverviewPrefix`, `studyOverview`) plus the non-factory keys (`["study-session", kind]` from `lib/studySession.ts`, `["strokes", character]`). `useStudyItems` pages through `api.listAllStudyItems` (backend cap 200) for the pre-redesign surfaces; `useStudyItemPages` is the Hoje grid's one-page-at-a-time infinite query (12 per page, `getNextPageParam` from the envelope's exact `total`); `useStudyItemPageQueries` is the item index's per-page reader (one 24-row query per page it needs, so "Carregar mais" never exceeds the server's 100-row cap); `useDictionaryPageQueries` is the Add/Import dictionary pane's per-page reader (one five-row page on desktop, every shown page on mobile). `useRelatedEntries` reads one 8-row related page behind the item detail's desktop `Pager`; `useRelatedEntryPages` is the mobile accumulated-page reader behind `LoadMore`; `useItemReadings` is the item detail's entry-filtered reading summary list (20 rows per page, full readings fetched separately by `useReadingText` only when selected). `useReadingHistory` is the Leitura rail's one 8-row summary page behind the desktop `Pager` (its `enabled` option lets the page call it beside the mobile reader without a stray request); `useReadingHistoryPages` is the mobile accumulated reader behind `LoadMore`. Both read the token-free summary contract; only a selected row calls `useReadingText` for the full reading. `useCharacterStrokes` sets `retry: false` (a 404 means "no stroke data") and `staleTime: Infinity` (stroke data never changes). `useStudySession` sits outside the `["study-items"]` prefix with infinite stale time and zero cache time, so study-item invalidation never refetches or reshuffles a running session. `useExtraStudy` keys on the two range instants under `["insights"]`, takes its stale time per observer (60 s on the dashboard, infinite in practice), and `invalidateAfterReview` is the single real-grade refresh policy: it invalidates the study-items, insights and study-overview prefixes so the grids, Extra Study and every Hoje aggregate stay current. `useAddStudyItem` invalidates the study-items, study-overview and related-entries prefixes so a queued row and its counter flip in place; `useBatchImportStudyItems` is the per-row batch request, and `useAddImportRefresh` is the one queue+counter refresh at a run's end (deferred so a thousand-row import does not refetch the queue per row). Practice calls no mutation, so nothing is invalidated. `priorityMutationOptions` owns the optimistic priority policy: it cancels the study-items queries, writes the predicted edge position into every cached list and the single-item cache, snapshots them for rollback, seeds the single item from the server response, and on settle invalidates the study-items prefix and the lesson-session key.

### `src/pages` — routed screens
**Purpose**: the ten screens — Hoje (dashboard), Biblioteca's item index and the Adicionar/Importar CSV workspace, study-item detail, Leitura, Progresso, Ajustes, and the full-screen lesson/review/practice flows — mounted at the new IA paths (`/`, `/biblioteca/*`, `/leitura`, `/progresso`, `/ajustes`). No shell destination renders the shared `Placeholder` any more.
**Files**: `frontend/src/pages/Dashboard.tsx`, `pages/ItemIndex.tsx`, `pages/AddImport.tsx`, `pages/StudyItemPage.tsx`, `pages/Reading.tsx`, `pages/Progresso.tsx`, `pages/Ajustes.tsx`, `pages/Lesson.tsx`, `pages/Review.tsx`, `pages/Practice.tsx`
**Seam(s)**:
- **Hoje dashboard** (`pages/Dashboard.tsx`, `api/queries.ts`) — one `useStudyOverview` request feeds every aggregate: the hero's `due_review_count` / `new_count` and the disabled-at-zero actions (`/review`, `/lesson`), the Caracteres chip counts (`item_count` / `leech_count`), the learned chart, the SRS half-pie and the seven-day forecast. The sticky right rail (`lg:sticky`) holds SRS Stages then Próximas revisões; the DOM order is the settled mobile order (hero → Caracteres → Itens aprendidos → Estudo extra → SRS → Próximas revisões). Each panel owns its loading skeleton and empty copy. The character grid reads one page of 12 at a time through `useStudyItemPages` (`sort=stability_asc` for Todas, `leech=true` for Sanguessugas — the server order is authoritative) and appends via the `+` tile, never paging through the queue.
- **Item index seam** (`pages/ItemIndex.tsx`, `lib/itemIndex.ts`, `lib/useMediaQuery.ts`) — Biblioteca's browse surface: filters (state / HSK / raw POS / search / due range, OR within a field and AND across), the three server sorts and the presentation position all live in the URL, so opening an item and returning restores the list. The filter panel is its own `ItemFilters` component; its search draft is local (instant typing) and commits to the URL from the change handler, while an external URL change resets the draft during render and "Limpar filtros" remounts the search box so a pending debounce cannot re-apply it. `update` patches the current URL rather than a captured state, so a pending search cannot overwrite a filter chosen meanwhile. Desktop reads one 24-row server page behind `Pager`; mobile reads every 24-row page it has shown behind `LoadMore` (never above the server's 100-row cap). Both presentations are rendered from the same `DataList` rows, panel states are per panel (loading skeleton, error + retry, beyond-end recovery, empty with a clear-filters action), and rows carry the ghost/bolt status chips. The detail page's back link prefers the list href carried in router state.
- **Study session seam** (`pages/Lesson.tsx`, `pages/Review.tsx`, `api/queries.ts`, `lib/studySession.ts`) — each flow reads `GET /study/session?kind=…` once on entry (`staleTime: Infinity`, `gcTime: 0`) and hands the received item order to `Quiz` verbatim — no client filter or sort. The backend owns lesson membership (all `learning`, pinned first then shuffled remainder) and review membership (due, non-learning, fully shuffled); a remount or refresh is a new session with a new shuffle. `useReviewMutation` invalidates the `["study-items"]` prefix, the insights and study-overview prefixes, the single item and its review list, but not the running session. `Quiz` is the one practice stage for all three same-shaped flows.
- **Practice seam** (`pages/Practice.tsx`, `lib/extraStudy.ts`, `components/Quiz.tsx`) — reads `bucket` and the two range instants from the URL, re-reads the same `["insights", "extra-study", …]` query the dashboard used and holds it with infinite stale time, then hands the bucket's items to `Quiz` with `record={false}`. That seam issues no grade request at all; the stage reads `Prática`, takes the cyan band, carries the `SrsIntactChip` `SRS intacto` chip and the summary says nothing was recorded.
- **Practice stage seam** (`components/Quiz.tsx`, `components/PracticeBand.tsx`, `components/PracticeDock.tsx`, `components/FlipCards.tsx`) — one bounded stage shared by Lesson, Review and Practice. `Quiz` owns the `info → prompt → revealed` state machine, keyboard, submission and presentation switch (`useMediaQuery` at `lg`); `PracticeBand` renders the mode gradient (`from-violet-600 to-violet-800` / `from-rose-500 to-accent-600` / `from-cyan-600 to-sky-800`), header, progress segments, pinyin, the one glyph slot and meaning; `PracticeDock` renders the four grade keys and rollback/advance. One glyph per phase: the `StrokePlayer` replaces the cards in `info` (175px desktop / 150px mobile), the `FlipCards` are hidden in `prompt`, and in `revealed` the cards are the answer with a `Ver traços →` / `← Cartões` pill swapping the player in place. The revealed middle shows the consequence of the chosen note, not a second glyph. Mobile keeps the band and question strip, the dock is one 44px key row with a full-width advance, rollback moves to the band's top bar, and both edges pad with the safe-area insets; grading is tap-only. Flips use `motion-reduce:transition-none`.
- **Grade keys** (`lib/practiceGrades.ts`, `components/PracticeDock.tsx`) — the four notes (`again`/`hard`/`good`/`easy`) with label, hotkey, SRS hint (`reaprende agora`, `volta em ~1 dia`, `~3 dias`, `~7 dias`), a 4px left bar in the note's `--color-srs-*` stage hue and the matching fill class. Unselected keys are slate; the chosen key fills with its hue and keeps the white ring while only the other labels recede (their bars keep colour). `gradeConsequence(rating)` writes the revealed middle line (`Bom · volta em ~3 dias`) and `gradeByHotkey` is the keyboard lookup.
- **Flip card layout** (`lib/flipCards.ts`, `components/FlipCards.tsx`) — `flipLayout({count, available, min: 56, cap: 132, gap})` sizes one tile per character, shrinking to the 56px floor and then wrapping into balanced rows (a 7-character word at 300px is 4+3 at 67px). Tiles are keyed per occurrence, so duplicate glyphs keep their own tile; the corner radius is `min(20, max(6, size × 0.16))`, so a long word never produces circles.
- **Extra Study panel** (`components/ExtraStudyPanel.tsx`, `pages/Dashboard.tsx`, `lib/extraStudy.ts`) — the two fixed buckets as tabs with their server totals always visible, at most four hanzi tiles of the active bucket in received order, and a `Praticar` action disabled at zero. One implicit recent-window insight request (no date inputs) drives the panel; the practice URL carries its range.
- **Priority quick actions** (`components/ItemPrioritySection.tsx`, `pages/StudyItemPage.tsx`, `lib/lessonQueue.ts`) — priority editing lives on the item page only now; the section renders only while the item is still `learning`, in an `inline` variant inside the desktop identity header and the `compact` panel variant in the mobile order (facts → priority → stroke card). `PriorityActions` carries front/back/remove with item-scoped names, an inline confirmation before the destructive remove, and inline `role="alert"` failures. The quiz runner carries no priority controls, so a running session order stays frozen.
- **Study item detail seam** (`pages/StudyItemPage.tsx`, `components/ItemReadings.tsx`, `components/RelatedEntries.tsx`, `components/ItemTrajectoryChart.tsx`, `lib/itemFacts.ts`) — replaces the old page outright. The identity header leads with the hanzi, tone-coloured pinyin and the priority controls, then `fsrsFacts` renders the card as plain-language state/interval/measurement rows. Desktop keeps Trajetória → Leituras → Relacionados in the main column and only `Traços` (175px viewer) in the sticky rail; mobile uses a compact identity header, then facts → priority → the open 104px stroke card first among the study panels, followed by the same three panels. Each panel owns its loading, error and empty state through `PanelState`. The page branches presentation on the `lg` breakpoint through `lib/useMediaQuery.ts`, handing each component an explicit `Presentation` so the components stay presentational; the panel subtree is keyed by item id so a related-word hop never inherits the previous selection.
- **Leitura workspace seam** (`pages/Reading.tsx`, `components/ReadingHistory.tsx`, `components/ReadingArticle.tsx`, `components/ReadingGenerator.tsx`) — desktop is three panes inside the shell: the history rail (one 8-row summary page behind its own `Pager`, so paging never pushes the article), the centre (one wrapping generator bar over the `max-w-[68ch]` article column, its meta line and extra-word note) and the word-inspector rail over the collapsed vocabulary/topic accordions. The page owns the selection id, the page number and the selected token; the history reads summaries only and selecting a row is what triggers `useReadingText` for the full reading. Mobile splits the same surface into `role="tablist"` segments — Leitura (article, then the compact `Nova leitura` card), Histórico (`LoadMore`) and Painéis (vocabulary + topics) — and renders the selected token as the sticky `WordSheet`. Model choice persists under `reading.model`, numeric inputs are clamped to the backend bounds, and reading-format labels come from `i18n/readingFormat.ts`; the article's attempt trail and offered-vocabulary accordions are preserved. The mobile/desktop branch is the `lg` breakpoint through `lib/useMediaQuery.ts`.
- **Add/Import workspace** (`pages/AddImport.tsx`, `components/DictionarySearchPanel.tsx`, `components/CsvImportPanel.tsx`, `lib/addImport.ts`) — one Biblioteca workflow behind both `/biblioteca/adicionar` and `/biblioteca/importar`. Desktop renders dictionary search and CSV import side by side behind one `useStudyOverview` queue counter; mobile renders only the search pane plus the desktop-only CSV note (the item index hides its import link at that width, and a direct `/biblioteca/importar` visit falls back to Adicionar). Dictionary rows are five-per-page server pages — `Pager` on desktop, accumulating `LoadMore` on mobile — with the HSK chip and a per-row enqueue control that flips `Adicionado` to `Na fila`; CSV import parses locally, sends one row at a time, and layers `pending`/`loading` over the backend outcome with live progress, the created/skipped/error tiles, twelve-row result pages and an inline candidate picker that resolves only its own ambiguous row. Both panes reuse `DataList`, `Pager` and `LoadMore`; interactive lists omit `rowHref` so their row controls stay usable.
- **Progresso** (`pages/Progresso.tsx`, `lib/progress.ts`) — the progress surface assembled from shipped aggregates only: the estimated level and HSK coverage plus the vocabulary profile from `useVocabularyProfile` (the `/reading-vocabulary` aggregate), the learned curve from `useStudyOverview`, and the five latest words through one bounded `useStudyItemPages({ sort: "created_desc" }, 5)` page carrying their `SrsStageChip`. Each panel owns its loading, error and empty state through `PanelState`; nothing is aggregated on the client and no backend contract is added.
- **Ajustes** (`pages/Ajustes.tsx`, `lib/localSettings.ts`) — the per-browser handwriting preferences in one `Panel`: the toggle and its tolerance preset read and write the same localStorage keys the quiz uses, the preset is disabled while the check is off, and the copy shows how many mistakes the chosen tolerance allows on a six-stroke character. Reached from the desktop account chip and the mobile Mais sheet; no server call.

### `src/components` — chrome, shared primitives, quiz and Chinese-language widgets
**Purpose**: the responsive app shell, the shared component vocabulary (including the list, pager, load-more, filters and SRS stage chip), the quiz/lesson machinery, the stroke-order renderers and the reading/vocabulary panels.
**Files**: `frontend/src/components/{AppShell,Placeholder,PageHeader,Panel,Skeleton,EmptyState,Toast,QueryState,ChartAxes,DataList,Pager,LoadMore,ListCount,ItemFilters,ItemBadges,HskChip,SrsStageChip,SrsIntactChip,icons,Quiz,PracticeBand,PracticeDock,FlipCards,HandwritingQuiz,FullScreenMsg,StrokeGlyph,StrokePlayer,StrokeOrder,StrokeOrderPanel,Pinyin,Hanzi,ItemReadings,ItemTrajectoryChart,RelatedEntries,VocabularyPanel,ReadingTopicsPanel,ReadingArticle,ReadingGenerator,ReadingHistory,WordInspector,CharacterTileGrid,StudyItemTile,PriorityActions,ItemPrioritySection,ExtraStudyPanel,UpcomingReviews,SrsHalfPie,ItemsLearnedChart,HskCoverage,VocabularyBreakdown,RecentWords,ProgressBar,DictionarySearchPanel,CsvImportPanel}.tsx`
**Seam(s)**:
- **DataList seam** (`components/DataList.tsx`) — the shared one-model/two-presentations list: a dense desktop table and stacked mobile cards rendered from the same rows and column model in the same DOM, with `secondary` columns dropped from the cards. When `rowHref` is given every row links to the same destination from both widths; a list with interactive row content omits it and renders plain rows, so enqueue buttons and candidate pickers stay usable. The caller's `chips` slot carries the status marks. It never re-sorts: the server's page order is rendered as received.
- **Pager seam** (`components/Pager.tsx`, `components/ListCount.tsx`) — the desktop paginator: numbered pages (windowed with ellipses on long lists) and previous/next disabled at the ends, with the shared `Mostrando N de M` caption derived from the rows actually received and the envelope's exact total. `pageSize` is required so each surface passes its own density.
- **LoadMore seam** (`components/LoadMore.tsx`, `components/ListCount.tsx`) — the mobile list footer: the same caption plus a full-width `Carregar mais` that disappears once `shown === total`; no infinite scroll.
- **Character tile and grid** (`components/StudyItemTile.tsx`, `components/CharacterTileGrid.tsx`, `lib/tileBadges.ts`) — the one tile used by every character grid and the item page header: hanzi-only, fluid (`aspect-square w-full`) with the SRS level colour on the bottom edge, linking to `/biblioteca/itens/:id`. `tileBadges(item)` derives the overlays from the DTO alone — a ghost for `is_leech`, then a bolt for a non-null `priority_position` — rendered by `ItemBadges` as the drawn `ghost`/`bolt` icon chips with a pt-BR `aria-label` and a `title`, never emoji. `CharacterTileGrid` lays tiles out in a fluid `auto-fill` column flow in the received order (never re-sorted) and appends the dashed `+` tile when given `onLoadMore`. The quiz runner renders none of this.
- **SRS stage chip** (`components/SrsStageChip.tsx`, `lib/srs.ts`) — the one place the five display-group colours meet their stage labels; consumed by the item index, the item detail header and later SRS-bearing surfaces.
- **Hoje panels** (`components/SrsHalfPie.tsx`, `components/UpcomingReviews.tsx`, `components/ItemsLearnedChart.tsx`) — the three overview-fed panels: the half-pie splits the five display groups in `GROUP_COLOR` order with the total in the centre and a two-column legend (the empty track alone at zero); the forecast renders exactly the seven local-day rows with a quiet proportional bar; the learned chart is chart-only and both charts render their axes through the shared `ChartAxes` frame (HTML ticks beside the plot, local-date labels below). Day labels go through `lib/format.ts`'s local parse — never `new Date("YYYY-MM-DD")`.
- **Progresso panels** (`components/HskCoverage.tsx`, `components/VocabularyBreakdown.tsx`, `components/RecentWords.tsx`, `components/ProgressBar.tsx`) — the progress surface's presentational bodies: `HskCoverage` draws one proportional bar per HSK level from `lib/progress.ts`'s joined rows and owns the "HSK totals unavailable" empty state; `VocabularyBreakdown` shows the queued-word total, the per-class bars ordered greatest first and the adjective-shortage note, with its own empty states (no words, or words with no class); `RecentWords` renders the bounded recent list as item links with `HskChip` and `SrsStageChip`, and its own empty copy. `ProgressBar` is the one clamping meter both panels use. The page owns every query and `PanelState`, so the bodies stay presentational.
- **Shell seam** (`components/AppShell.tsx`, `lib/navigation.ts`) — the desktop sticky command bar (brand, four global sections, `Buscar` + a working `⌘K`/Ctrl+K shortcut, the `Retomar` due chip from `useStudyOverview`, and the account chip for Ajustes) over a `max-w-6xl` content column, plus the mobile top app bar and pinned bottom tabs (Hoje / Biblioteca / Leitura / Mais) with the Mais overflow sheet (Progresso / Adicionar / Ajustes). Every destination, label and icon comes from `lib/navigation.ts`; both mobile edges pad through `lib/safeArea.ts`. `Lesson`/`Review`/`Practice` are routed outside it.
- **Primitives seam** (`components/PageHeader.tsx`, `Panel.tsx`, `Skeleton.tsx`, `EmptyState.tsx`, `Toast.tsx`, `QueryState.tsx`, `Placeholder.tsx`) — the shared vocabulary every later surface composes: page heading, bounded panel, decorative loading block, the `PanelState` gate with its `PanelLoading`/`PanelError` blocks, per-panel empty guidance, transient undo/dismiss toast and the one shared stand-in for an unmigrated route (optionally linking its section's already-built sub-surfaces).
- **Icon seam** (`components/icons.tsx`) — the inline stroke-SVG set (`ICON_NAMES`, 24×24, round caps/joins, 1.7 stroke) with the `ghost`/`bolt` badge pair at 2.6; `Icon` is decorative unless given a `label`.
- **Stroke coordinate seam** (`components/StrokeGlyph.tsx`) — the one renderer for hanzi-writer's raw (Y-up, top-left at `(0, 900)`) data: it converts the paths into a top-down 0..1024 SVG box and draws the faint outline plus the first `revealed` fills. `StrokeOrder` (quiz) and `StrokePlayer` both consume it, so the transform lives in one place; `HandwritingQuiz` feeds the same cached data through `charDataLoader` so it never hits a CDN.
- **Stroke player seam** (`components/StrokePlayer.tsx`) — the shared player shape: exactly one character in a caller-sized square viewer, a 44px per-character picker whenever the word has more than one hanzi, a `4/7 · traço 1/6` counter and ◀ ▶ stepping. The viewer is sized from the caller alone (175px desktop rail / 104px mobile card on the item detail; 175/150 on the practice band), so switching characters never resizes it. The item detail and the practice stage share it; `StrokeOrderPanel`/`StrokeOrder` remain the quiz's pre-migration renderers.
- **Practice stage and dock seams** (`components/Quiz.tsx`, `PracticeBand.tsx`, `PracticeDock.tsx`, `FlipCards.tsx`, `SrsIntactChip.tsx`) — the one stage the lesson, review and practice flows render. `Quiz` keeps the runner semantics: nothing is graded until a note is picked, rollback clears the note then steps back, advance is disabled without a note, and the keyboard keeps `1–4`, `Enter`/Space, `Backspace`/`z` and `Esc`. `PracticeBand` owns the gradient identity per mode, the header (`Sair`, mode pill, the `SrsIntactChip` `SRS intacto` chip, handwriting toggle/tolerance, counters, mobile rollback icon), the per-item progress segments, pinyin, the one glyph slot and meaning; `PracticeDock` owns the four note keys plus rollback/legend/advance. On mobile the band keeps the safe-area top inset, the dock is one 44px key row over a full-width advance with the home-indicator affordance, and rollback lives in the band; desktop bounds the whole stage at 720px. `FlipCards` is the per-phase glyph: hidden in `prompt`, the answer in `revealed`, with the pill swapping the `StrokePlayer` in place.
- **Item readings seam** (`components/ItemReadings.tsx`, `api/queries.ts`) — the item page's Leituras pane: entry-filtered summary rows only (format, topic, model, extra-word count, date, preview) inside a bounded internally scrolling list. Selecting a row is what fetches the full `SavedReadingText`; desktop shows the match snippet and detail below the list, mobile expands it inline under the tapped row. The match renders the server's `before/hit/after` exactly — no synthetic ellipses, so the article-edge clamp is preserved.
- **Reading history seam** (`components/ReadingHistory.tsx`, `api/queries.ts`) — the Leitura rail/list: 8-row summary rows (`#id`, format, topic, extra-word count, date, preview) rendered in received order. Desktop ends in `Pager` inside the rail; mobile ends in `LoadMore`. Both are presentational over the page-owned rows, so the same summary contract feeds both presentations and the list never fetches a full reading.
- **Word inspector and sheet seam** (`components/WordInspector.tsx`) — the one `WordDetail` shared by the persistent desktop `WordInspector` and the mobile sticky `WordSheet` (`<dialog>`, docked above the tab bar and padded by `lib/safeArea.ts`). It renders hanzi, tone-coloured pinyin, part of speech, definitions and the extra-word flag; `Adicionar ao estudo` appears for any token with a dictionary entry and reads `Na fila` (disabled) once `useStudyItems` shows it queued, so the queue state survives the add's invalidation.
- **Trajectory chart seam** (`components/ItemTrajectoryChart.tsx`, `components/ChartAxes.tsx`, `pages/StudyItemPage.tsx`) — chart-only trajectory on the shared `ChartAxes` frame: stability (days) on the left, difficulty 1–10 on the right, local date labels below, a legend above. No snapshot list. Empty history renders its own copy; the page panel owns loading and retry through `PanelState`.
- **Related entries seam** (`components/RelatedEntries.tsx`, `api/queries.ts`) — the shared-character route's rows in the server's order: a two-up paged grid at 8 per page with `Pager` on desktop, one growing list with `LoadMore` on mobile. A queued row links to `/biblioteca/itens/:id`; an unqueued row adds inline through `useAddStudyItem`, which invalidates the related prefix so the row flips to "na fila".
- **Quiz phase seam** (`components/Quiz.tsx`, `lib/quizPractice.ts`) — the `info → prompt → revealed` phase machine over an item queue, with the `PRACTICE_GRADES` notes (`again`/`hard`/`good`/`easy`) as the review submission and keyboard hotkeys; `HandwritingQuiz` is the optional interactive check. Its `record` prop defaults to true; practice passes false, which skips the grade call entirely while keeping the same runner and local accuracy. `QUESTION_LABEL`/`NEXT_LABEL`/`stageBandClass` are the stage copy and mode identity. `Quiz.dom.test.tsx` exercises the phase contract through the DOM lane: reveal by click, grade by hotkey, advance by Enter, rollback from the top bar, and the one-glyph-per-phase swap.
- **Pinyin rendering** (`components/Pinyin.tsx`) — consumes `lib/pinyin.ts` syllables and the `.tone-1`–`.tone-5` classes from `index.css`.

### `src/i18n` — backend-enum display labels
**Purpose**: pt-BR labels for backend enums and codes that reach the UI.

### `src/lib` — pure helpers
**Purpose**: the unit-testable surface — CSV parsing, pinyin conversion, the display-only SRS ladder, local settings, progress profiles, extra-study range arithmetic, the item-index URL state, Add/Import paging, paging arithmetic, item facts, the practice grade/flip layouts and formatting.
**Files**: `frontend/src/lib/csv.ts`, `lib/pinyin.ts`, `lib/srs.ts`, `lib/localSettings.ts`, `lib/progress.ts`, `lib/format.ts`, `lib/studySession.ts`, `lib/navigation.ts`, `lib/safeArea.ts`, `lib/tileBadges.ts`, `lib/lessonQueue.ts`, `lib/itemFacts.ts`, `lib/extraStudy.ts`, `lib/quizPractice.ts`, `lib/practiceGrades.ts`, `lib/flipCards.ts`, `lib/itemIndex.ts`, `lib/addImport.ts`, `lib/pagination.ts`, `lib/useMediaQuery.ts`
**Seam(s)**:
- **Navigation model seam** (`lib/navigation.ts`) — `PATHS` (every chrome destination, including the resume route), `itemPath(id)`, `SECTIONS` (Hoje / Biblioteca / Leitura / Progresso), `MOBILE_TABS` (the three sections that survive as tabs), `MAIS_ITEMS` plus the shared `ADICIONAR`/`AJUSTES` destinations, and the active-path rules (`isActiveSection`, `isMaisTabActive`). Every chrome and every item link reads this model; a destination is never hard-coded twice.
- **Safe-area constants** (`lib/safeArea.ts`) — `SAFE_AREA_TOP`/`SAFE_AREA_BOTTOM` for the chrome edges and `DOCKED_BOTTOM` for anything floating above the mobile tab bar; `index.html` opts into `viewport-fit=cover` so the insets are real.
- **Tile badge seam** (`lib/tileBadges.ts`) — `tileBadges(item)` returns the ordered ghost/bolt descriptors (ghost first) with their kind, pt-BR label and title; `ItemBadges` maps the kind to its drawn icon and renders exactly this list.
- **Lesson queue and priority seam** (`lib/lessonQueue.ts`) — `isLearning`/`isPinned`/`priorityStatus` drive the item page's priority section; `predictPriorityPosition` and `applyCachedPriority` are the pure halves of the optimistic update; `priorityErrorMessage` owns the pt-BR inline copy, including the 409 graduation sentence.
- **Item facts seam** (`lib/itemFacts.ts`) — `fsrsFacts(item)` turns the FSRS card into the item page's plain-language facts line: translated state, relative next-review/último-review intervals (with the exact instant as a tooltip), stability in days, difficulty out of 10 and the added date. Missing measurements render as an em dash, never as a zero-looking number.
- **CSV seam** (`lib/csv.ts`) — `parseStudyItemsCsv(text)` accepts a hanzi/pinyin header, comma or semicolon, quoted fields; it never validates pinyin (the backend reports per-row).
- **Add/Import paging seam** (`lib/addImport.ts`) — `DICTIONARY_PAGE_SIZE` (5) and `CSV_RESULT_PAGE_SIZE` (12) with `dictionaryPageRequests` (one numbered page on desktop, every shown page on mobile) and `dictionaryShown` (the honest caption count per presentation).
- **Pinyin seam** (`lib/pinyin.ts`) — `parsePinyin(numbered)` → `{text, tone}` and `toAccented`; the tone-mark placement rule lives here, not in a component.
- **SRS display ladder** (`lib/srs.ts`) — derived from the backend's continuous `stability` (days), not a stored level; `LEVELS`/`GROUP_ORDER`/`GROUP_COLOR` are the single ladder and palette. The overview owns the group counts; the client only maps a card to its level and colour.
- **Local settings** (`lib/localSettings.ts`) — `useHandwritingEnabled`/`useHandwritingTolerance` persist per browser; `allowedMistakes(strokeCount, tolerancePercent)` scales the tolerance by the character's own stroke count. Ajustes and the quiz read and write the same keys.
- **Progress profile seam** (`lib/progress.ts`) — `hskCoverageRows(summary)` joins the vocabulary aggregate's `coverage_by_level` with its `by_hsk_level` counts and orders the levels numerically (empty when the dictionary carries no HSK totals); `estimatedLevelLabel(level)` owns the "HSK N" / "Iniciante" copy; `categoryRows(by_category)` translates and orders the grammatical classes greatest first, dropping empty ones.
- **Session query policy** (`lib/studySession.ts`) — `studySessionKey(kind)` and `STUDY_SESSION_QUERY` pin the session hooks outside the `["study-items"]` prefix with infinite stale time and zero cache time.
- **Extra Study range** (`lib/extraStudy.ts`) — local calendar-day helpers: `toDay`/`addDays`, the last-three-day default window the dashboard uses, the local-day instants (`dayStartInstant`/`dayEndInstant`, also consumed by the item index's due range), `rangeInstants` (from → local midnight, to → next local midnight), the bucket list/predicate, and `parsePracticeSearch` for the practice URL. Local-day parsing itself is `format.ts`'s `parseLocalDay`.
- **Item index state seam** (`lib/itemIndex.ts`) — `parseItemIndex`/`serializeItemIndex` own the URL shape (`state`, `hsk_level`, `pos_tag`, `search`, local-day `due_from`/`due_to`, `sort`, desktop `page`, mobile `shown`), dropping malformed values and omitting defaults. `itemIndexQuery` maps it onto the API filters and local-midnight due instants; `itemIndexRequests` yields one 24-row server page for desktop and every shown page for mobile; `dueRangePatch` keeps the typed due range ordered; `toggleValue` and `hasFilters` are shared by the filter chips.
- **Pagination seam** (`lib/pagination.ts`) — `ItemPageRequest`, `pageCount`/`pageOffset`/`pageWindow` and `nextPageOffset` (the one accumulating-reader rule every infinite query shares, from the envelope's exact total), the generic paging math every list surface shares, so `Pager` is not coupled to the item-index module.
- **Presentation breakpoint** (`lib/useMediaQuery.ts`) — `useMediaQuery` reads a CSS media query through `useSyncExternalStore` rather than a mirroring effect; the item index uses it to choose the desktop server page + `Pager` versus the mobile shown pages + `LoadMore` (the `md` breakpoint Tailwind renders at), and the item detail uses the `lg` breakpoint to choose its desktop rail versus the mobile panel order, and `Quiz` uses it to choose the bounded desktop stage versus the full-height mobile flow; every responsive component takes the shared `Presentation` type.
- **Practice copy and write seam** (`lib/quizPractice.ts`) — `topBarTitle`/`summaryCopy` own the practice variant's labels: `Prática`, the `SRS intacto` run, and the summary saying nothing was recorded; `stageBandClass` gives each mode its band identity (violet Lição, cerise Review, cyan Prática) and `QUESTION_LABEL`/`NEXT_LABEL` own the phase copy. `submitRevealedGrade` is the only place a revealed advance decides whether to call the grade mutation; with `record: false` it never calls the submit callback, so practice issues no write at all.
- **Practice notes seam** (`lib/practiceGrades.ts`) — `PRACTICE_GRADES` is the one table of note labels, hotkeys, SRS hints, stage-hue bar classes and fill classes; `gradeOf`/`gradeByHotkey` resolve a note for the dock and the keyboard, and `gradeConsequence` writes the revealed middle line. The dock and the runner consume it, never a second inline copy.
- **Flip card layout seam** (`lib/flipCards.ts`) — `flipLayout({count, available, min: 56, cap: 132, gap})` is the pure size-and-wrap rule: shrink per character to the floor, then balanced rows (4+3 for a seven-character word at 300px). `FlipCards` renders its rows and keeps duplicate glyphs keyed per occurrence.
- **Formatting** (`lib/format.ts`) — `fromNow`/`formatDateTime`/`formatDate`, all `pt-BR`, plus `parseLocalDay`/`formatDayLabel`/`formatWeekdayLabel` for the overview's `YYYY-MM-DD` local days (parsed from parts, never as UTC midnight).

**Seam(s)**:
